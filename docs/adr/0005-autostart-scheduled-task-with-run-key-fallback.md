# ADR-0005：开机自启——用户级计划任务优先，HKCU Run 回退

- 状态：已采纳（2026-09）
- 关联：`install.ps1`；`supervisor.py`

## 背景

网关需要常驻。两台机器实测出两种可行路径与一条死路：

- 计划任务（`Register-ScheduledTask` 用户级）：免管理员、可配失败自动重启（每分钟、无限次）、登录触发、单实例 `IgnoreNew`——在一台机器上成功；
- HKCU Run 注册表键：最简单可靠，但没有失败重启——另一台机器上计划任务注册被环境拒绝（Access denied）后退而用之，稳定运行；
- **死路**：schtasks/管理任务（要管理员）、启动文件夹 VBS/BAT 链（易被 Defender 拦、无守护）。

## 决策

`install.ps1` 依次尝试：① 用户级计划任务（登录触发 + 任务失败每分钟重启 + 不限时长 + 允许电池）；② 失败则自动回退 HKCU Run 键（`pythonw supervisor.py`）。两种方式拉起的都是 `supervisor.py` 守护——它自带应用层健康探测（每 5 秒真打 `/healthz`，连续 3 次失败才重启网关）与单实例锁，因此即便走 Run 键（无任务层重启），应用层自愈仍然完备。

## 被否掉的方案

- **只做计划任务**：在拒绝注册的机器上直接失败，用户卡死在第一步；
- **只做 Run 键**：丢掉任务层失败重启的双保险；
- **VBS/BAT 启动文件夹**：实测易被 Defender 误杀且无守护。

## 后果

- `uninstall.ps1` 必须两种方式都清理（已实现）；
- 文档要说明当前用的是哪种方式（安装脚本结束时打印）；
- `/healthz` 只代表网关自身，不因 CC Switch 暂未启动而误杀网关——守护的判定边界。
